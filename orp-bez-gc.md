# Говорят «Реактивность не бесплатна»

И первым делом добавляют в язык GC, с подсчетом ссылок в куче и оптимизируют "stop the world". Мы же сегодня задумаемся не об оптимизации байтиков, а об оптимизиации архитектуры

Но у нас же уже есть безопасный яп дома, папа!

Да, Rust экономит на сборщике мусора, но чето он слишком сложный. Zig отдаёт память программисту, как и С, плюсы. Остальные живут с GC и его издержками. 

Предлагаю попробовать добавить реактивность в это семейств

Реактивный граф знает всегда что и кого нужно дропнуть. Сборщик выясняет то же самое только обходом кучи. И у нас даже есть наглядный пример: 

### Excel, самый популярный реактивный ЯП в мире

Формулы в Excel это чисто функциональная программа, а с `LAMBDA` ещё и полная по Тьюрингу. Excel строит дерево зависимостей между ячейками, изменили ячейку --- всё зависимое помечается dirty и пересчитывается. Никто не подписывается на `A1` и никто от неё не отписывается, ссылка в формуле и есть подписка. Стёрли формулу и её зависимости исчезли вместе с ней. Сборщика мусора для формул там нет и никогда не было.
Им бы только виртуальный рендеринг добавить 

Бухгалтеры так живут с 1979 года. А мы пишем `subscribe()` в каждом компоненте.

### Откуда реактивные ноги растут

У Алана в Smalltalk главное это сообщения и позднее связывание: кто ответит решается в момент обращения, но актуальность состояния поддерживают руками, MVC придумали что бы удобнее контролировать состояние как раз. Pull-реактивность доводит позднее связывание до значения: сколько это равно, тоже решается в момент обращения.

Дмитрий Карловский в 2017 году назвал эту парадигму Объектно Реактивным Программированием (ОРП) Метод при вызове запоминает что прочитал, кеширует результат и сбрасывает кеш когда прочитанное поменялось. 

### Сборщик не всегда спасает от утечек

Граф знает что значение больше никто не читает, он может не только выкинуть кеш, но и закрыть то что за этим значением стоит: сокет, таймер или подписку. Сборщик так не умеет. Для него важна только достижимость, а подписка держит замыкание, замыкание держит компонент, и всё это прекрасно достижимо хотя никому не нужно)

Сборщик убирает память и ничего не знает про сокеты, файлы и таймеры. В Java для этого был `finalize()`, его признали ошибкой, и с Java 18 (JEP 421) финализацию собираются удалить. Поэтому в языках со сборщиком ресурсы закрывают руками: `try-with-resources`, `using`, `defer`.

Отдалим должное Erlang. Процесс владеет своими портами и ETS-таблицами, умер процесс и всё что его закрылось, куча у каждого процесса своя поэтому общего stop-the-world нет. Косяк в том чт рантайм не знает нужен ли кому то этот процесс. Еще и руками нужно значения проталкивать 

### Аутбокс и Кафка

На бэке тот же граф собирают руками и называют паттерном. Сервис заказов пишет заказ в базу и событие в Кафку, между двумя записями падает, это dual write. Лечат transactional outbox: событие кладут в таблицу той же транзакцией, Debezium или поллер шлёт его в Кафку, доставка at-least-once, поэтому каждый потребитель хранит id обработанных и выкидывает дубли. Из событий потребитель собирает свою проекцию, например остатки на складе.

Проекция это производное значение от чужого состояния, а `OrderCreated` по сути «твой кеш протух». Таблица outbox работает очередью инвалидации, поллер рассылает уведомления, дедупликация чинит повторы. Push-реактивность из таблицы, демона и брокера.

На wire склад просто читает заказы:

```typescript
object $bog_wire_outbox_reserve {

	sku: text
	orders: $bog_wire_outbox_orders

	taken( order: $bog_wire_outbox_order ) = order.sku == sku ? order.qty : 0

	qty = orders.all.map( taken ).sum

}

object $bog_wire_outbox_stock {

	orders: $bog_wire_outbox_orders

	solid total( sku: text, next?: int ) = next ?? 0

	reserve( sku: text ) = $bog_wire_outbox_reserve {
		sku <= sku
		orders <= orders
	}

	free( sku: text ) = total( sku ) - reserve( sku ).qty

}
```

Заказы это список с `upsert` по id, поэтому повторный заказ ничего не задваивает:

```typescript
action same_order_twice_counts_once() {
	stock.total( "tea", 10 )
	orders.place( "o1", "tea", 3 )
	orders.place( "o1", "tea", 3 )
	assert( stock.free( "tea" ) == 7 )
}
```

Отмена возвращает товар без компенсирующего события, а объект резерва уничтожается, когда его перестают спрашивать. Две системы граф атомарными, конечно, не сделает, транспорт между ними нужен всё равно. Но по нему можно гнать состояние с версией, а не события, так синкается Гипер База.

### wire

Все утечки выше были про то, что ресурс можно положить мимо графа. Так появился [wire](https://github.com/b-on-g/wire), язык, где мимо графа положить нельзя:

  * переменных нет, лямбд нет, в `map`, `find`, `upsert` передаются именованные методы;
  * состояние это параметр `next?`, писать в него можно только из `action`;
  * тела мемо чистые, это проверяет компилятор;
  * `solid` это модификатор метода, а не вызов где-то в теле.

Ссылка на объект может лежать только в результате атома, значит граф видит каждую. Объект принадлежит первому атому, который его вернул, и умирает вместе с ним. Значения неизменяемые и считаются счётчиком ссылок, цикл из неизменяемых значений не собрать, так что он не течёт.

Компилятор на TS, генерирует C и собирает его `zig cc`. Каждый метод становится обычной функцией, вся реактивность сидит в `wire_read`:

```c
static void F_bog_wire_shop_line__sum( wire_obj* self, const wire_val* keys, const wire_val* next, wire_val* out ) {
	wire_val t165 = wire_read( self, &M_bog_wire_shop_line__catalog, NULL, NULL );
	wire_val t166 = wire_read( self, &M_bog_wire_shop_line__sku, NULL, NULL );
	wire_val t167[] = { t166 };
	wire_val t164 = wire_read( t165.obj, &M_bog_wire_shop_catalog__price, t167, NULL );
	wire_val t168 = wire_read( self, &M_bog_wire_shop_line__qty, NULL, NULL );
	wire_val t163 = { .i = t164.i * t168.i };
	*out = t163;
}
```

Это `sum = catalog.price( sku ) * qty`. Так можно писать и руками на C против `rt/rt.h`, язык нужен только чтобы компилятор не дал завести таймер мимо графа)

Весь «сборщик мусора» рантайма:

```c
static void reap( void ) {
	while( rt.touched.len || rt.orphans.len ) {
		wire_ids touched = ids_take( &rt.touched );
		for( int i = 0; i < touched.len; ++i ) evict( touched.items[ i ] );
		ids_free( &touched );

		wire_ids orphans = ids_take( &rt.orphans );
		for( int i = 0; i < orphans.len; ++i ) {
			wire_node* node = get( orphans.items[ i ] );
			if( node && !node->has_owner && !node->root ) destroy( orphans.items[ i ] );
		}
		ids_free( &orphans );
	}
}
```

Кучу никто не обходит, разбираются только узлы, которых коснулись за тик.

После каждого теста рантайм сверяет число живых узлов и значений с тем, что было до теста, и при расхождении валит сборку с `leaked N values, M nodes`. Проверку я проверял, вбрасывал утечку, тест краснел. Пример магазина в нативной сборке весит 78 904 байта, пиковый RSS 1,5 МБ на macOS.
